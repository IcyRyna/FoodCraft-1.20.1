# 迁移依据与差异记录

## 固定基线

旧源码固定为 `1.7.10` 分支提交 `523515c4988e485adbcf5eb51c73caec71d5361d`，包含 152 个 Java 文件、约 17,217 行 Java 源码、420 张 PNG 和 `zh_CN`、`zh_TW`、`en_US` 三套语言文件。源码版本为 1.2.0；[原发布记录](https://archives.mcbbs.co/read.php?tid=441072) 的 1.2.1 更新主要增加矿物词典支持。迁移清单区分源码数据与发布记录，现代标签保留对应兼容入口。

`content-manifest.json` 记录 359 个展开条目，其中 356 个为本模组实际注册内容，2 个映射到原版羊肉，1 个是旧调试物品。24 个果酱 / 饼干 / 蛋糕 metadata 变种拆成独立 ID，机器亮灭合并到方块状态。配方清单含 118 条机器配方和 141 条工作台配方。

## 玩法与数值

- 食物的最终饥饿值取旧构造器实际传给 `ItemFood` 的第二参数，而不是形参 `amount`。饱和度系数为该值 / 3；这些结果已在实际注册的 189 种食用物品上核对。
- 普通饮料不附加黄金饮料效果。黄金葡萄 / 苹果汁保留 36000 tick、等级参数 4；黄金酒为 3600 tick、等级参数 4；普通酒为 600 tick、等级参数 3 的随机正面或负面组合。全部效果由服务端执行。
- 羊肉及熟羊肉使用原版物品、食用属性和掉落规则，去掉旧额外羊肉掉落事件。
- 鱿鱼保留额外 3 个生鱿鱼肉掉落。果味食品、酿酒、特殊主食效果、刀具增产、净化工具、手册与收集奖励保留。
- 17 种作物、葱、17 种果树和果实方块保留。旧作物在第 5 / 6 阶段的提前收获与随机数量按源方法提取；水稻与糯稻使用各自正确的种植与掉落链。
- 果树形状使用旧代码的逐块几何。旧果实方块本身不会按原版树叶规则自动腐烂；移植保留此行为，同时在生成前检查障碍，防止树覆盖容器。
- 鸡蛋和雪球的堆叠上限保持 64。多功能工具以构造材质的 5000 耐久统一管理，修复旧右键逻辑以 2000 提前销毁的矛盾。
- 补齐生鱿鱼肉、玉米、红薯和净化水的 4 条原版熔炉加工配方；净化水每次产出 2 个盐。Fabric 的原版熔炉增加针对本配方的数量与输出容量处理，两端均验证连续两次加工及输出已有 63 个盐时不消耗原料。
- 按旧版 `RemoveRecipe` 保留面包、蛋糕、南瓜派三个原版工作台配方的禁用行为，避免绕过 FoodCraft 的加工路线。禁用配方实现原版 `CraftingRecipe` 接口，能正常同步与重载。
- 普通酒与黄金酒都使用饮用动作；数值和随机效果在服务端执行。
- 平底锅物品保持旧版 `ItemBlockPDG` 的堆叠上限 1。清单新增旧完整注册名、metadata、亮灭注册名的合并映射以及有效堆叠上限；多功能工具的有效耐久为 5000。
- 果味蛋糕放置复用已经注册的对应 `BlockItem`，避免 Forge 注册表冻结后临时构造新物品。8 种蛋糕的实际放置、单次物品消耗与第一口饥饿值均执行验证。
- 黄金果酱、饼干、蛋糕物品保留闪光。黄金蛋糕不添加金饼干的药水效果；按 `BlockJinputaoDG.updateTick` 保留随机恢复一口咬痕的行为。旧方法误标记 `@SideOnly(CLIENT)`，专用服务器无法执行，本次统一为服务端随机 tick；吃完最后一口仍移除蛋糕。
- 链式初始化中的硬度与脚步声音也按最终设置提取，修正材料方块被现代默认硬度覆盖的问题。树苗、作物和葱的旧选取边界由常量表达式计算，运行时核对全部方块的硬度、声音和已定义边界。

现代地牢等战利品采用附加的 FoodCraft 加权池，保留旧注册的物品、权重与数量区间；不同 Minecraft 版本的原版战利品池本身不同，不能把每个箱子的总体概率视为 1.7.10 原版池的完全复制。

打草的 18 种 FoodCraft 种子保留权重总和 35（蔬菜种子为 1，其余为 2）。[Forge 1.7.10 的原始草籽池](https://github.com/MinecraftForge/MinecraftForge/blob/1.7.10/src/main/java/net/minecraftforge/common/ForgeHooks.java) 另有权重 10 的小麦种子，因此 FoodCraft 附加池采用 `1/8 × 35/45` 的触发概率，保持独有种子的获取频率；剪刀采草不额外产出 FoodCraft 种子。现代原版小麦种子的池继续由原版提供，因此原版种子与独有种子可以同时出现；这与旧版的单池抽取形式有区别。

## 内容清单字段

`legacy` 为旧字段 / 注册名，metadata 变种附 `:0` 等后缀。`id` 为现代完整 ID。`kind`、`legacy_class`、`constructor_args` 记录分类和构造依据。食物记录 `nutrition`、`saturation`、`always_edible`、`effect`；工具记录 `durability`；作物记录种植目标、各阶段掉落；方块记录模型贴图、碰撞和硬度等源数据。`fixes` 说明合并、补全及修复。

`status: generated` 表示由固定源生成；实际验证状态由 `content-check.json`、双端 `runtime-content.json` 与验证报告共同说明，不把生成状态冒充测试通过。

`content-validation.json` / `content-validation.csv` 将每项内容的获取入口、关联配方、有效数值和验证覆盖放在同一条记录中。测试为类别或配方组覆盖时明确标出，不把单个模型引用检查写成每个物品都经过人工视觉验收。
