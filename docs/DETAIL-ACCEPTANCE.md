# 第二轮细节验收与修复

日期：2026-10-02。对象：FoodCraft 2.0.0 的 Forge / Fabric 1.20.1 移植。第二轮针对第一轮报告未穷尽的边界，实际复现问题、修改实现、加入回归测试，并重新检查发布 JAR。第一轮文件保留在 [历史报告](evidence/round1-verification.md)，当前交付状态以 [验证报告](VERIFICATION.md) 为准。

## 实际发现及修复

| 问题 | 复现结果 | 修复与通过证据 |
|---|---|---|
| 火候包的数值溢出与滑块端点 | 原菜单按钮 ID 为 `100 + 火力`，原版包用有符号 byte，火力 28 以上会变负；旧坐标计算无法到 0 | 编码改为 `2 + 火力`，滑块覆盖 0–100；101 个值走原生包往返，真实锅和平底锅 GUI 分别点击 100 / 50 / 0 |
| 自动化把主料送进错误槽 | 漏斗反序投放高压锅配方的猪肉、蛋、米，旧插入按第一个空槽排列，配方失配 | 依据配方的槽位角色和已有输入分配；相同材料多槽均衡。原生漏斗反序加工皮蛋瘦肉粥成功，双端批量插入及模拟 / 回滚通过 |
| Fabric 已拆除机器的旧物品接口仍可插入 | 保留的 Transfer API storage 在实体移除后接受物品 | 实体和侧面插入 / 提取均检查移除状态；旧 storage 拒绝继续使用，并测试事务回滚 |
| JEI 丢失配方要求的数量 | CraftTweaker 的 2 木棍 → 2 面包，实际转移按钮只放入 1 根木棍 | 使用共用数量规划、受限匹配、旧材料返还空间检查、快照验证和服务端一次性提交；236 个基线单批 / 最大批次场景、重叠标签、满背包和过期快照测试通过；真实 JEI 按钮转移当前 118 条配方，其中脚本探针取代被脚本删去的原米饭配方 |
| 同 ID 配方重载沿用旧批次进度 | 旧配方进行 5 / 20 tick 后阻塞输出，把同 ID 改为 30 tick 配方，仍留 5 / 20 | 配方内容指纹在输出暂停前核对。变化时归零并更新时长；同配方 NBT 加载继续原进度。最终产物及两根木棍消耗一致 |
| 建筑高度边界损失种子 | 顶层耕地的上方超出世界高度，放置失败仍消耗种子 | 预先检查高度、世界边界及交互许可，仅成功放置后扣除；18 种种子原生使用测试全部通过 |
| 两张旧贴图降低整个图集 mip 级别 | 锅 100×32、桃子 18×18 导致 Minecraft blocks 图集从 mip 4 降到 1 | 锅透明补边到 128×32 并改模型水平 UV；桃子裁掉透明一像素边框到 16×16。原像素 / 可见像素完全保留，真实客户端图集恢复 mip 4 |
| 油炸机把油量显示成水量 | 机器提示与 JEI 页脚使用通用水标签 | 独立油量文本，补齐简中、繁中和英文；语言与资源检查通过 |
| Fabric 服务器配置缺少客户端同步 | 原实现各端只读自己的 `wrench`，设置不同会造成操作提示与服务端行为不一致 | 登录同步服务端设置，断开连接清除覆盖。实际专服 `false`、客户端文件 `true`，连接后客户端输出 `wrench=false`；关闭扳手后的六级镐回收规则两端各 54 个场景通过 |
| Fabric 统一验证入口运行目录无效 | Loom 把绝对 Windows runDir 接在模块路径后，形成重复盘符路径，启动失败 | Loom 配置采用相对 runDir，JavaExec 实际 workingDir 使用绝对目录，支持不同盘符工作目录；完整 `verify.ps1` 实际运行通过 |

前后三轮具体输出保留在 [回归复现](evidence/round2/fabric-regressions-reproduced.log)、[高度等边界复现](evidence/round2/fabric-boundaries-before-fix.log)、[JEI 修复前](evidence/round2/jei-before-fix.log)、[进度修复前](evidence/round2/progress-before-fix.log) 和最终双端 GameTest 日志中。油标签与配置同步属于界面 / 端间一致性修正，不把它们表述为已经发生的存档损坏或复制。

原生客户端证据见 [Forge](evidence/round2/native-details-forge.log)、[Fabric](evidence/round2/native-details-fabric.log)。这两次早于最后补充的随机效果断言，逐 ZIP 条目比较证明只有 `DetailGameTests.class` 改变，所有生产代码与资源完全相同：[Forge 比较](evidence/round2/forge-native-ui-byte-comparison.json)、[Fabric 比较](evidence/round2/fabric-native-ui-byte-comparison.json)。最终 JAR 另实际跑过多人 / 重启；Fabric 关闭扳手的完整细节客户端又直接使用最终 JAR。

所有客户端都放在独立 Windows 桌面，启动器不申请桌面切换权限，不调用 `SwitchDesktop`。用户反馈隔离桌面仍能听见声音、偶尔光标跳到中央后，立即停止两个正在运行的测试客户端；这些中断的运行不算通过。启动器新增主音量 0 与强制 Java agent，阻止测试进程的光标重定位、鼠标锁定、主动聚焦和 OpenAL 音源播放，另经不访问真实输入设备的变换自测。它只用于验收，不在发布模组 JAR 内。

JEI 点击由 Minecraft / JEI 原生事件接口执行，截图来自 Minecraft 帧缓冲。它验证实际 GUI 事件链、菜单包与服务端处理，不声称由人手点击。防护的本次变换标记及拦截计数随完成日志保存。

## 验收中的失败如何处理

`makeMockPlayer()` 没有真实 ServerPlayer 的部分踩田和掉落语义，早期断言出现 0 掉落；换成脱离在线列表的真实 ServerPlayer，再测试原生行为。相邻随机种子的首个布尔值高度相关，早期普通酒样本只覆盖一组；改为散列种子，验证所有分支。细节客户端计时曾被基础夹具重置，使每步多等待约 40 tick；修正计时并重跑。这些是验证夹具问题，不列为已交付模组的玩家 bug。

开发长测曾因同时编译热替换输出出现 `NoSuchMethodError`，该失败不算通过。本轮冻结全部 Java 和资源后独立跑长测；只修改报告及 Python 验证工具。默认 GameTest、发布 JAR 安装和源码包重建分别保留证据，不能互相冒充。

## 结论边界

本轮实际复现的问题均已修复，并增加了能够重新触发对应边界的回归检查。仍未穷尽：每个物品 / 模型在所有光照及朝向的人工审美校对、所有语言文字的人工翻译校对、第三方管道组合、所有高延迟 / 失序网络排列、Linux / macOS，以及每种机器所有可能的背包填充与操作交错。当前日志和测试证明列出的场景通过，不等于对任何模组组合保证没有 bug。
